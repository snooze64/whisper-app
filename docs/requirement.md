# 音声文字起こしアプリケーション 要件定義書

## 1. プロジェクト概要

### 1.1 目的
オンプレミス環境で動作する音声・動画ファイルの文字起こしアプリケーションを開発する。
主に、オンライン会議（Zoom、Microsoft Teams等）の録画ファイルの文字起こし、会議録音の議事録作成、動画コンテンツの字幕作成を目的とする。

### 1.2 スコープ
- Webベースのユーザーインターフェース
- OpenAI Whisperを用いた高精度な音声認識
- 話者分離機能による複数話者の識別
- ファイルアップロード機能による文字起こし処理
- 複数ユーザーの同時利用に対応

---

## 2. 機能要件

### 2.1 コア機能

#### 2.1.1 ファイル文字起こし機能
**概要**: 既存の音声・動画ファイルをアップロードして文字起こしを実行

**主要ユースケース**:
- オンライン会議（Zoom、Microsoft Teams等）の録画ファイル
- 対面会議やインタビューの録音ファイル
- 動画コンテンツの字幕作成

**対応ファイル形式**:
- 音声: MP3, WAV
- 動画: MP4

**処理内容**:
- 音声認識による文字起こし
- タイムスタンプ付きテキスト生成
- 話者分離（話者数は事前指定）
- 動画ファイルの場合は字幕ファイル（SRT/VTT形式）の生成

**ファイル制限**:
- 最大ファイルサイズ: 1GB（環境変数で変更可能）
- 保存期間: アップロード後24時間

### 2.2 音声認識エンジン

#### 2.2.1 使用モデル
- **エンジン**: OpenAI Whisper
- **対応モデル**:
  - Whisper Large-v3
  - Whisper Large-v3-turbo
- **モデル選択**: ユーザーが処理時に選択可能

#### 2.2.2 対応言語
- **メイン言語**: 日本語
- **多言語モード**: UI上でモード切り替え可能
  - 英語、中国語、韓国語など主要言語に対応

### 2.3 話者分離

#### 2.3.1 使用技術
- **ライブラリ**: Resemblyzer (https://github.com/resemble-ai/Resemblyzer)
- **話者数指定**: ユーザーが事前に話者数を指定
- **拡張性**: 将来的に他の話者分離技術に置き換え可能な設計

#### 2.3.2 出力形式
- 各発話に対して話者ID（Speaker 1, Speaker 2...）を付与
- タイムスタンプと共に話者情報を表示

### 2.4 処理キュー管理

#### 2.4.1 並列処理制御
- **方式**: GPUメモリ使用率のリアルタイム監視
- **動的スケジューリング**: 空きメモリがあれば次のタスクを自動実行
- **キュー管理**: メモリ不足時は順次処理

#### 2.4.2 GPU環境
- **GPU**: NVIDIA A100 40GB
- **実質利用可能メモリ**: 20-30GB（他タスクとの共用）
- **CUDA バージョン**: 11.8 または 12.1+
- **想定処理数**: Whisper Large-v3で1タスクあたり約10-12GB使用

### 2.5 ユーザー認証

#### 2.5.1 認証方式
- **プロトコル**: LDAP認証
- **対象**: 社内ユーザー

#### 2.5.2 権限管理
- **一般ユーザー**: 文字起こし機能の利用、自分の処理履歴の閲覧
- **管理者**: 全ユーザーの処理履歴の閲覧、システム設定の変更、ダッシュボードの閲覧

### 2.6 データ管理

#### 2.6.1 ストレージ
- **アップロードファイル保存期間**: 24時間
- **処理結果保存期間**: 24時間
- **自動削除**: 保存期間経過後に自動削除

#### 2.6.2 処理履歴管理
処理ごとに以下の情報を記録:
- ユーザー名
- 処理日時
- ファイル形式（MP3, WAV, MP4等）
- ファイル容量
- 処理にかかった時間
- 使用モデル（Large-v3 / Large-v3-turbo）
- 処理ステータス（成功/失敗）

### 2.7 管理者機能

#### 2.7.1 ダッシュボード
システムの利用状況を可視化:
- 総処理数（日別、月別）
- ユーザー別利用統計
- 処理時間の統計
- ファイル形式別の利用状況
- GPU使用率の推移
- エラー発生率

#### 2.7.2 システム設定
- 最大ファイルサイズの変更
- 保存期間の変更
- 並列処理数の上限設定
- メンテナンスモードの切り替え

### 2.8 テキスト編集機能

#### 2.8.1 機能概要
処理完了後のテキストをWeb UI上で編集可能:
- テキスト内容の修正
- タイムスタンプの調整
- 話者ラベルの変更
- 編集後の再保存・再エクスポート

## 3. 非機能要件

### 3.1 パフォーマンス
- **処理速度**: 1時間の音声ファイルを15分以内で処理（Large-v3-turbo使用時）
- **同時接続ユーザー数**: 最大20ユーザー
- **アップロード速度**: 1GBのファイルを5分以内にアップロード完了

### 3.2 可用性
- **稼働時間**: 24時間365日稼働（メンテナンス時を除く）
- **エラーハンドリング**: 処理失敗時の適切なエラーメッセージ表示
- **タイムアウト**: 長時間処理の場合も進捗状況を表示

### 3.3 セキュリティ
- **通信**: HTTPSを使用
- **アクセス制御**: LDAP認証による社内ユーザー限定
- **データ保護**: アップロードファイルと処理結果の24時間自動削除
- **ログ記録**: アクセスログ、処理ログの保存

### 3.4 保守性
- **モジュール設計**: 話者分離エンジンの交換可能な設計
- **設定の外部化**: 環境変数による設定管理
- **ログ管理**: 標準出力へのログ出力（Docker対応）

### 3.5 拡張性
- **水平スケーリング**: 将来的な複数GPU対応を考慮
- **モデル追加**: 新しいWhisperモデルの追加が容易な設計

---

## 4. システム要件

### 4.1 デプロイ環境
- **OS**: Linux
- **コンテナ**: Docker / Docker Compose
- **GPU**: NVIDIA A100 40GB（CUDA 11.8 or 12.1+）
- **アクセス方式**: ユーザーのローカルPCからHTTP/HTTPS経由

### 4.2 クライアント要件
- **ブラウザ**: Chrome, Firefox, Edge（最新版）
- **ネットワーク**: 社内ネットワーク経由でのアクセス

## 5. 今後の拡張機能（将来的な検討事項）

以下の機能は初期リリースには含まれないが、将来的に追加を検討:

### 5.1 リアルタイム文字起こし機能
- **概要**: オンライン会議中にリアルタイムで文字起こしを実行
- **実装方式の候補**:
  - システム音声キャプチャ（仮想オーディオデバイス使用）
  - デスクトップアプリ化（Electronなど）によるシステム音声直接取得
- **処理方式**: WebSocketによるストリーミング処理
- **想定ユースケース**: Zoom、Microsoft Teams等のオンライン会議中のリアルタイム議事録作成

### 5.2 ChatGPT連携機能
- **概要**: 文字起こし結果をChatGPTで自動処理し、議事録の要約や整形を実行
- **主要機能**:
  - プロンプトテンプレートへの文字起こし結果の埋め込み
  - デフォルトプロンプト（要約、アクションアイテム抽出など）の提供
  - ユーザー任意のカスタムプロンプトの作成・保存
  - 複数のOpenAI互換API対応（OpenAI、Azure OpenAI、ローカルLLMなど）
- **設定方式**:
  - OpenAI Base URLとAPIキーを環境変数で設定（システム全体で共通）
  - 利用可能なモデルは`{baseurl}/api/models`から動的に取得
  - ユーザーがモデルを選択可能
- **想定ユースケース**:
  - 会議の議事録要約
  - アクションアイテムの自動抽出
  - 重要トピックのハイライト
  - 多言語会議の翻訳
- **出力形式**:
  - 処理前テキスト（文字起こし結果）
  - 処理後テキスト（ChatGPT出力）
  - 両方のダウンロード・保存に対応

### 5.3 その他の拡張機能
- 用語辞書・カスタム語彙の登録機能
- 音声品質の自動評価
- 複数言語が混在する音声の処理
- API提供による外部システム連携
- クラウドストレージ（S3, GCS等）との連携

---

## 6. 制約事項

### 6.1 技術的制約
- CUDA 11.8/12.1+のサポートが必要
- GPUメモリが他タスクと共用のため、処理速度が変動する可能性
- Whisper Large-v3のメモリ使用量により、同時処理数に制限

### 6.2 運用制約
- ファイルサイズ上限: 1GB
- 保存期間: 24時間
- オンプレミス環境のみでの運用

---

## 7. 成功基準

- ユーザーが音声・動画ファイルをアップロードし、正確な文字起こし結果を取得できる
- 複数ユーザーが同時に利用してもシステムが安定稼働する
- 処理履歴と利用統計が適切に記録・表示される
- LDAP認証により社内ユーザーのみがアクセスできる
- GPU利用率を最適化し、複数タスクの効率的な並列処理が実現される
